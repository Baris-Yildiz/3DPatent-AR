    Maintenance notes

    This page documents intentional design decisions that look like bugs or omissions but are not. Read this before changing the related code.

    Review state is derived, never stored

    Patent has no moderation status column. Each submit/decision cycle is a row in design_reviews, and the effective state is computed on read:

    # app/models/review.py
def effective_review_state(reviews) -> ReviewState:
    if any(r.status == ReviewDecision.APPROVED for r in rows):
        return ReviewState.APPROVED          # terminal — wins outright
    latest = latest_review(rows)
    ...

    This preserves the full audit trail (every reject + resubmit) and keeps lifecycle fields off the core entity. Do not add a denormalised status column to patents_patent; query the reviews and call effective_review_state. See app.models.review.

    Two database sessions are intentional

    FastAPI is async and Celery is sync, so there are two engines against one DB: app.db.session (AsyncSession, asyncpg) for routes and app.db.sync_session (Session, psycopg2) for tasks. A route must use the async session; a task must use the sync one. Mixing them deadlocks or crashes — async drivers cannot run in a worker's sync context and vice versa.

    is_staff / is_superuser are dormant

    # app/models/user.py
role: Mapped[UserRole] = mapped_column(...)   # the real authorization gate
is_staff: Mapped[bool] = ...                  # inherited from the Django schema, unused
is_superuser: Mapped[bool] = ...              # unused

    Authorization is the single role column (USER / ADMIN / EXPERT). The two boolean columns are inherited from the original Django schema and intentionally left in place (dropping them is a migration with no benefit). Never gate behaviour on them.

    EXPERT and ADMIN are disjoint

    The role gates in app.api.deps are strict and separate: get_current_admin_user requires exactly ADMIN, get_current_expert_user requires exactly EXPERT. An admin cannot evaluate submissions and an expert gets no admin panel. This is deliberate separation of duties, not an oversight — do not let one role fall through to the other.

    The media token has no sub and a distinct scope

    # app/core/security.py
{"pid": patent_id, "scope": MEDIA_TOKEN_SCOPE, "exp": expire}

    Media capability tokens (used by QR links) deliberately omit sub and carry a media scope, so a leaked media token can't be used as a login (get_current_user rejects it) and an access token can't be used as a media token (verify_media_token checks the scope). Keep these properties if you touch token minting. See app.core.security.

    Image generation reuses the converter pipeline

    Hunyuan3D's GLB is not the finished product — it still needs the converter's Blender → DRACO re-export. Rather than duplicate the container plumbing, generate_from_image_task wraps the raw GLB in a ZIP and hands it to convert_patent_task as if it were a GLB upload. So there is exactly one conversion path and one thumbnail step. Don't add a parallel post-processing path for generated models. See app.worker.tasks.

    Thumbnailing is best-effort

    generate_thumbnail_task runs once (max_retries=0) and its finally block flips the patent to CONVERTED whether or not the render succeeded. A missing thumbnail must never gate an otherwise-finished model; callers fall back when /thumbnail returns 404.

    Converter containers run with no mounts

    Each ephemeral converter/thumbnailer container is created with --network none, --cap-drop ALL, --security-opt no-new-privileges, and no volume mounts. Inputs go in and outputs come out via docker cp. Do not "simplify" this by bind -mounting the media volume into the converter — the isolation is the point. The shell scripts run inside the container take the only user-controlled values as positional $1/$2 args, never interpolated into the script text, so they're unreachable by shell injection.

    Do not drop the container PIDs limit below 512

    # app/worker/tasks.py
CONTAINER_PIDS = "512"

    The converter (Blender + FreeCAD + xvfb) spawns many threads/processes. A --pids-limit of 100 caused SIGABRT crashes in production. Keep it at 512 or above.

    CONVERTER_IMAGE is a single source of truth

    The image tag lives once, in app.worker.celery_app, shared by the task that spawns containers and the orphan sweeper. Bumping it in one place can't desync them — don't hardcode the tag in tasks.py.

    Orphan converter cleanup on worker start

    If the worker is SIGKILLed mid-task, its finally block can't docker rm -f the spawned container. A worker_process_init handler prunes leftover youndria/arpatent containers on every worker process start (boot and worker_max_tasks_per_child recycles). Safe with --concurrency=1: no other task is running when the signal fires.

    Crash safety: task_acks_late + worker recycling

    The Celery worker runs with task_acks_late=True (a task isn't acked until it finishes, so a crash redelivers it), worker_prefetch_multiplier=1, and worker_max_tasks_per_child=50 (recycle the process to bound fd/memory leaks from the subprocess + docker CLI shellouts). The 30s stop_grace_period in compose pairs with this.

    Locarno data is not memoized in-process

    # app/data/locarno.py
def invalidate() -> None:
    return None   # no-op; reads go straight to the DB

    Production runs multiple uvicorn workers plus Celery workers; a per-process cache can't be invalidated across them, so an admin edit in one worker would leave the others stale. The read helpers query the DB every call instead. invalidate() is kept as a no-op at every mutation site so intent stays explicit if memoization ever returns. See app.data.locarno.

    Locarno integrity is enforced in application code

    Designs reference Locarno entries by plain string (patents_patent.locarno_*), with no foreign key to the lookup tables (5000+ subclasses, validated at the app layer). So the admin Locarno routes count referencing designs and refuse a delete (409) if any exist — never orphan a design's classification. See app.api.routes.admin.

    Fuzzy search uses pg_trgm word_similarity

    The catalog, expert queue, and admin list use Postgres pg_trgm word_similarity (not plain similarity) so long names aren't penalised for length, with a per-transaction threshold:

    await db.execute(text("SET LOCAL pg_trgm.word_similarity_threshold = 0.3"))
stmt = stmt.where(Patent.model_filename.op("%>")(q_clean))

    SET LOCAL is transaction-scoped. The pg_trgm extension and a GIN index must exist (created by migration).

    Last-admin protection

    The admin user routes refuse to demote, deactivate, or delete the last active admin, and an admin cannot change their own role/active status. This guarantees the system can never be locked out of all admin access. See app.api.routes.admin.
