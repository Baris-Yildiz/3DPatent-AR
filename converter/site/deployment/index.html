    Deployment

    Local development

    No separate Blender or FreeCAD installation is needed.

    python -m venv venv
venv\Scripts\activate        # Windows
# venv/bin/activate          # Linux / macOS
pip install -r local_python_requirements.txt

    local_python_requirements.txt includes:

    Package Purpose
    bpy==4.5.3 Blender as a pip-installable Python package
    fake-bpy-module IDE type stubs for bpy (not the real runtime)
    freecad-stubs IDE type stubs for FreeCAD APIs
    ufbx FBX parser
    rich / rich-logger Logging console
    regex Log pattern matching

    CAD formats not available on Windows

    FreeCAD is only available in the Docker container. STEP and IGES conversions will fail in the local venv.

    Docker

    The Docker image builds both Blender and FreeCAD from source. Expect the build to take a long time (30–60+ minutes depending on CPU core count).

    Build

    docker build -t 3dpatent-converter .

    The Dockerfile:

    1. Installs build toolchain (gcc-14, g++-14, cmake, Blender/FreeCAD dependencies)
    2. Clones and builds Blender at a pinned commit, then packages it as a .whl
    3. Installs the Blender wheel into a Python 3.11 venv
    4. Clones and builds FreeCAD 1.0.0, installs to /usr/local
    5. Installs Python dependencies from docker_python_requirements.txt
    6. Copies the converter source

    Run

    docker run 3dpatent-converter

    The default entrypoint runs test.py via xvfb-run for headless rendering:

    xvfb-run -a /venv/bin/python3.11 test.py

    xvfb-run creates a virtual framebuffer so Blender can render without a display.

    docker_python_requirements.txt vs local_python_requirements.txt

    The Docker requirements are a minimal subset — bpy, fake-bpy-module, and freecad-stubs are excluded because:

    • bpy is compiled from source and installed as a .whl during the Docker build
    • fake-bpy-module and freecad-stubs are IDE-only stubs with no runtime use

    Environment variables

    All runtime configuration is passed through environment variables managed by ConverterArgs. See Environment management for details.
